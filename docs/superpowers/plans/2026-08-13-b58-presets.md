# BMW B58 Presets and Grouped Picker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the BMW B58B30M0 and B58B30M1 as validated factory presets, extend the injector catalogue to real port-injection sizes, and replace the engine picker with a manufacturer-grouped dropdown.

**Architecture:** Two new entries in the existing `ENGINE_PRESETS` array carry published engine data; their VE, spark and fuel tables are generated by the existing `factoryCalibration` rather than hand-authored. A new `PRESET_GROUPS` export derives manufacturer grouping from data already on each preset, so the picker's structure is assertable in plain Node with no React. The JSX consumes that shape through a native `<select>`.

**Tech Stack:** JavaScript (ES modules), React 18, Vite, Vitest, ESLint, `tsc --checkJs` for JSDoc types. Python 3 + matplotlib for the offline preset-fitting harness only.

## Global Constraints

Copied from `CONTRIBUTING.md` and the spec. Every task's requirements implicitly include this section.

- **Nothing adds horsepower.** Every part must change airflow, pressure, temperature or fuel delivery and let power fall out of the physics. No `power *= 1.05`. No per-engine multiplier — `src/sim/airflow.js:5-7` forbids it.
- Physics lives in `src/sim/`. No engineering maths in `src/ui/`.
- Empirical numbers live in `src/sim/coefficients.js` with a comment explaining what they represent. No bare magic numbers elsewhere in `src/sim/`.
- Colours, fonts and status hues come from `src/ui/theme.js` tokens. No hard-coded hex in components.
- Node 20+.
- Never edit `src/sim/coefficients.js` to make a single preset fit. A coefficient is global and moves every other engine.
- Never update `tests/fixtures/fingerprint.sha256` just to make a suite green. Every regeneration in this plan is paired with a reviewed report diff.
- Out of scope, deliberately: compressor boost ceilings (issue #9), the "Custom (based on N54)" label (issue #13), the UI overhaul (issue #6).

**Pre-flight adjudication (settled by the human partner, not open for re-litigation):**
Task 3's group-ordering test asserts the literal manufacturer order **and** the derived
first-appearance order. The derived check alone recomputes its expectation with the same
rule the implementation follows, so both could be wrong together; the literal list is
written independently of the code and closes that gap. Neither assertion replaces the
other.

/**
 * Presets grouped by manufacturer, in first-appearance order.
 *
 * The picker needs headings once the list outgrows a flat stack of buttons. Deriving
 * the grouping here rather than in the component keeps it assertable in plain Node —
 * the same reason `applyPreset` returns a patch instead of applying one — and means
 * the JSX renders a shape rather than computing one.
 *
 * Order comes from {@link ENGINE_PRESETS} itself, never from a second list kept
 * alongside it. A separate ordering table would be free to drift out of agreement
 * with the presets it claims to order; this cannot.
 *
 * @type {{manufacturer: string, presets: Preset[]}[]}
 */
export const PRESET_GROUPS = ENGINE_PRESETS.reduce((groups, preset) => {
  const group = groups.find((g) => g.manufacturer === preset.manufacturer);
  if (group) group.presets.push(preset);
  else groups.push({ manufacturer: preset.manufacturer, presets: [preset] });
  return groups;
}, /** @type {{manufacturer: string, presets: Preset[]}[]} */ ([]));
```

// wheel. Used where a list has grown past what a stack of PickList buttons can carry.
//
// `groups` is [{ label, options: [{ label, value }] }]; `extra` holds options that
// belong to no group and render after all of them.
function GroupedSelect({ groups, extra = [], value, onChange }) {
  return (
    <div style={{ position: 'relative', marginBottom: 13 }}>
      <select
        value={value}
        onChange={(e) => onChange(e.target.value)}
        style={{
          width: '100%', appearance: 'none', WebkitAppearance: 'none',
          padding: '11px 34px 11px 13px', borderRadius: 9,
          border: `1px solid ${T.line}`, background: T.panel2, color: T.ink,
          fontFamily: T.sans, fontSize: 13, fontWeight: 600,
        }}
      >
        {groups.map((g) => (
          <optgroup key={g.label} label={g.label} style={{ background: T.panel, color: T.ink2 }}>
            {g.options.map((o) => (
              <option key={o.value} value={o.value} style={{ background: T.panel2, color: T.ink }}>{o.label}</option>
            ))}
          </optgroup>
        ))}
        {extra.map((o) => (
          <option key={o.value} value={o.value} style={{ background: T.panel2, color: T.ink }}>{o.label}</option>
        ))}
      </select>
      <ChevronDown
        size={16}
        style={{
          position: 'absolute', right: 12, top: '50%', transform: 'translateY(-50%)',
          color: T.ink2, pointerEvents: 'none',
        }}
      />
    </div>
  );
}
```
